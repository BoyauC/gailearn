# Next Word Prediction 維護注意事項

本目錄是部署於 GitHub Pages 的繁體中文互動式教材，主要對象為臺灣國中生。教材說明：AI 依上下文與統計關聯預測後續文字；語句流暢或權重較高，不代表內容正確或已完成查證。

修改本目錄前請先閱讀本文件。教材企劃、案例說明與宣傳素材另存於 Obsidian：`宣傳片及互動教材素材用/國中-互動式教材-CH1-AI的預測與學習.md`。

## 修改範圍

- 只修改 `gailearn/next-word-prediction`，除非使用者明確要求整合其他教材。
- 文字調整優先修改 UTF-8 CSV，不要把案例文案複製進 JavaScript。
- 不覆寫使用者已調整的文案；修改氣候或生態地質案例時，同步更新 `scripts/build-expanded-cases.mjs`，避免重建資料時被覆寫。
- 未收到明確指令時，不 Commit、Push、建立或合併 Pull Request。

## 檔案用途

- `index.html`：第一層入口及追蹤碼。
- `css/style.css`：版面、色彩、平板與響應式規則。
- `js/game.js`：抽題、畫面流程、自迴歸路徑與結果判定。
- `data/cases.csv`：案例設定、回饋、查證內容與來源。
- `data/openings.csv`：每組誤導開場對應的完整路徑。
- `data/segments.csv`：開場文字片段與可疑詞設定。
- `data/nodes.csv`：候選詞、權重、下一群組及選後說明。
- `assets/images/sisi-60427.png`：首頁思思角色。

## 不可破壞的互動規則

1. AI 介面文字使用「預測」「候選」「權重」「上下文關聯」，不描述為 AI「知道」或「相信」。
2. 球體大小、亮度與百分比只是教學模擬權重，不表示正確性，也不宣稱為特定 LLM 的真實輸出。
3. 每次選詞後，下一輪候選必須依完整已選路徑切換；不可固定候選或只依排序增減百分比。
4. 每輪三選一；選擇後立即停用同組球體，顯示深色粗體 `reason` 與 `5 → 1` 倒數，約 5 秒後再前進。
5. `prediction_steps` 決定 3 層或 4 層流程，進度、倒數、結果頁都不可寫死為 4 層。
6. 可信度判斷不是計分題，結果頁必須保留玩家原始選擇。
7. 結果頁依序呈現原始 AI 敘述、玩家路徑與權重、玩家生成敘述、查證內容、落差說明與來源。
8. 結果判定依序為：符合查證事實 → 回到本局誤導開場 → 其他不符合事實的路徑。
9. 即使路徑符合查證內容，仍須提醒「預測結果正確不等於 AI 已完成查證」。

## CSV 維護規則

- 全部使用 UTF-8；含逗號、換行或雙引號的欄位必須正確使用 CSV 引號。
- 每個 `case_id + group_id` 剛好有 3 個候選，整數權重合計 100。
- 非最後一步的三個候選各自指向不同 `next_group`；最後一步留白。
- 4 層案例應有 40 個群組、120 個節點、81 條路徑；3 層案例應有 13 個群組、39 個節點、27 條路徑。
- `segments.csv` 的 `case_id + opening_id` 順序必須連續，並在 `openings.csv` 有且只有一筆對應。
- `matching_path` 必須是 `nodes.csv` 中實際可走出的完整路徑。
- `verified_compare_terms` 必須存在於 `verified_story`，並和 `comparison_path_groups` 的語意位置一致。
- 每個案例至少保留一筆可信查證來源。

## 平板與視覺

- 對外名稱固定為「AI的預測與學習」，維持暖米色、草綠與卡其配色。
- 平板是主要設計基準，橫式最佳；直式平板、PC 與手機仍須完整可用。
- 平板主要按鈕至少 56px 高，一般點按區至少 44×44px，正文至少 16px。
- 三個候選在橫式平板保持水平排列；裝置旋轉不得重置案例或路徑。
- 關鍵資訊不可只依賴 hover 或紅綠色；所有互動支援鍵盤、清楚焦點及 `aria-live`。
- 思思圖片不可變形、裁切臉部或改色；平板上的「下一個詞」使用 HTML 疊加。

## 修改後最低檢查

1. 執行 `node scripts/validate-game-data.mjs`。
2. 執行 `node --check js/game.js`。
3. 文字修改需確認 UTF-8 顯示、CSV 載入與對應案例畫面。
4. 版面修改需至少檢查 1024×768 橫式平板、768×1024 直式平板、360px 手機與 1440×900 PC。
5. 若修改流程或資料，完整走過批判閱讀、預測、可信度判斷與三種結果頁。
6. 確認 JavaScript console 無錯誤，且 CSV 或圖片載入失敗時有可理解的提示。
